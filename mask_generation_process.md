# Current Auto-Mask Generation Process

This document describes the current `v2` automatic mask generation pipeline for
custom MVTec-style datasets. The goal is convenience: the user provides normal
images, a few defect images, and optionally a text description. No manual bbox
or mask drawing is required.

## Input Layout

Expected dataset layout:

```text
dataset_root/
  custom_part/
    train/good/*.png
    test/scratch/*.png
    ground_truth/scratch/*_mask.png   # generated by auto-masks
```

Run:

```bash
cd v2
python -m iadgen_v2.cli auto-masks --config configs/custom_auto_masks_template.yaml
python -m iadgen_v2.cli prepare --config configs/custom_auto_masks_template.yaml --no-download
```

The main config block is `auto_masks`.

## Step 1: Qwen Defect Localization

`auto-masks` uses local `Qwen/Qwen2.5-VL-3B-Instruct` to inspect each real
defect image and return a rough bounding box.

The prompt asks for strict JSON:

```json
{
  "bbox_xyxy": [x1, y1, x2, y2],
  "defect_type": "scratch",
  "confidence": 0.9,
  "evidence": "short visual explanation"
}
```

The folder name remains authoritative for the defect label. For example,
`test/scratch/000.png` is treated as `scratch` even if Qwen reports another
label.

The Qwen box is not used directly as the final mask. It is only a search region.

## Step 2: Candidate Mask Generation

The default candidate order is:

```yaml
auto_candidate_modes:
  [normal_anomaly, soft_patch, sam2_heatmap, pixel, residual, multi_linear, linear, procedural]
```

### `normal_anomaly`

This is the default first choice. It fits robust local texture statistics from
`train/good` normal images, scores defect-image pixels by how unusual they are
inside the Qwen box, suppresses components that look like normal repeated
texture, and builds an adaptive envelope.

Adaptive envelope behavior:

- elongated evidence -> `scratch_band`
- compact/scuffed evidence -> `patch`

This is currently the most practical default for wood scratches.

### `soft_patch`

Uses heatmap evidence and morphology to create an irregular patch. It is useful
for scuffs, abrasions, or multiple small marks.

### `sam2_heatmap`

Uses Qwen box plus heatmap prompt points with SAM2 when available. This remains
useful for object-like defects, but it is often poor for fine scratches because
scratches are texture changes, not clean objects.

### `pixel` and `residual`

Use local contrast or nearest-normal residual evidence. These are lightweight
fallbacks.

### `multi_linear`, `linear`, `procedural`

These are fallback/proposal masks. They can look cleaner than the evidence but
may invent geometry, so auto-selection avoids them for patch/multiple-scratch
descriptions when evidence-based candidates are viable.

### Optional DINOv2 Candidates

`dinov2_memory` and `dinov2_fusion` are implemented but not enabled by default.
They compare DINOv2 patch tokens against a normal-image memory bank, inspired by
recent anomaly detection work. They can be useful for research comparison, but
for thin scratches they often produce coarse blob-like masks.

To test them, explicitly add them to `auto_candidate_modes`.

## Step 3: Candidate Scoring And Selection

Each candidate receives QC and a score. The score considers:

- empty mask rejection
- too-small or too-large mask area
- component count
- border touching
- scratch elongation
- text alignment, such as `dark`, `light`, `horizontal`, `vertical`, `diagonal`
- candidate type bonuses and penalties

For patch-like or multiple-scratch descriptions, auto-selection prefers
evidence-based candidates and avoids selecting fabricated line/procedural masks
when a viable evidence mask exists.

## Step 4: Dual Mask Outputs

The selected mask is not used as one universal mask. The pipeline now writes
purpose-specific variants:

| Variant | Purpose |
| --- | --- |
| `eval_tight` | Tight pseudo-label for MVTec `ground_truth` compatibility |
| `training_medium` | Default Phase 3 adapter-training mask |
| `training_wide` | Wider edit/training candidate for ablations |
| `inpaint_soft` | Soft mask candidate for SD inpainting |

Current defaults:

```yaml
ground_truth_mask_variant: eval_tight
training_mask_variant: training_medium
eval_tight_radius: 0
training_medium_radius: 4
training_wide_radius: 9
inpaint_variant_radius: 12
inpaint_variant_blur: 2.0
write_variant_overlays: true
```

This separation is important. The tight pseudo-label is kept for compatibility,
while Phase 3 can use the wider training mask so adapter training is not forced
to reconstruct only thin/noisy pixels.

## Step 5: Written Artifacts

For each defect image, `auto-masks` writes:

```text
dataset_root/<category>/ground_truth/<defect_type>/<stem>_mask.png
outputs/<exp>/auto_masks/qwen/metadata.jsonl
outputs/<exp>/auto_masks/qwen/masks/<category>/<defect_type>/*_refined.png
outputs/<exp>/auto_masks/qwen/masks/<category>/<defect_type>/*_inpaint.png
outputs/<exp>/auto_masks/qwen/mask_variants/<category>/<defect_type>/*_eval_tight.png
outputs/<exp>/auto_masks/qwen/mask_variants/<category>/<defect_type>/*_training_medium.png
outputs/<exp>/auto_masks/qwen/mask_variants/<category>/<defect_type>/*_training_wide.png
outputs/<exp>/auto_masks/qwen/mask_variants/<category>/<defect_type>/*_inpaint_soft.png
outputs/<exp>/auto_masks/qwen/overlays/<category>/<defect_type>/*.png
reports/<exp>/auto_masks/qwen/summary.md
```

The metadata row includes:

- `mask_path`
- `eval_mask_path`
- `training_mask_path`
- `mask_variant_paths`
- `mask_variant_overlay_paths`
- selected refinement mode
- candidate scores
- QC status
- Qwen bbox and raw text

## Step 6: Prepare Split Integration

`prepare` still consumes standard MVTec-style `ground_truth` masks.

Additionally, when auto-mask metadata exists, the split manifest records:

```json
{
  "mask_path": ".../ground_truth/scratch/000_mask.png",
  "eval_mask_path": ".../000_eval_tight.png",
  "training_mask_path": ".../000_training_medium.png"
}
```

Phase 3 prefers `training_mask_path` when present. If it is absent, Phase 3
falls back to `mask_path`.

## Current Interpretation

These masks are automatic pseudo-labels, not human ground truth.

Recommended interpretation:

- `eval_tight`: compatibility and rough pseudo-segmentation
- `training_medium`: default for adapter training
- `training_wide`: generation/ablation candidate
- `inpaint_soft`: SD inpainting edit region

For final academic segmentation claims, official or human masks are still
preferred. For scarce-data generation with `31` normal images and `3` defect
images, these masks are intended to bootstrap Phase 3/4 rather than provide
perfect pixel-level annotations.

## Known Limitations

- Pale scuffed patches blended with wood grain remain difficult.
- Thin scratches may require a wider training mask than their true visible
  pixels.
- SAM2 can segment object-like regions but often fails on texture-only defects.
- DINOv2 patch maps are useful anomaly signals but can be too coarse for final
  scratch masks.
- The contact-sheet overlays should be reviewed before trusting a run.
